The Missing Trophy

At 04:07 on Saturday the night guard found an empty gift box where the Golden Gear should have been. The Hall of Trophies was locked all night. The only witnesses are database tables: door-card swipes, purchases, messages, club lists and a hackathon sign-in sheet. You are the detective, and your only tool is SQL.

How to play. Each of the six chapters of the investigation gives you one task. Write a query in the editor and press Run (or Ctrl/Cmd + Enter). When your result contains the clue, the next chapter unlocks and the case board updates. Stuck? Open the hint ladder. When you are sure, accuse someone, but a wrong accusation costs you rank. Everything here is invented: the institute, the people and the data. Read Chapter 10 if the SQL feels new.

What am I looking at?

The page contains a small relational database (about 120 people, 7 700 card swipes, 1 200 purchases and 500 messages), built from a fixed seed so every student sees the same case. The SQL engine is the same pure-JavaScript engine as the Chapter 10 lab. Nothing is sent to a server.

On screenLecture concept
Schema browserTables, columns, types, primary keys and foreign keys. The little arrow on a column shows which table it references; that is what you JOIN on.
Chapter 1 · door logSELECT … FROM … WHERE … BETWEEN … ORDER BY: filtering rows by value and by time. Times are stored as text YYYY-MM-DD HH:MM, which sorts in time order.
Chapter 2 · last sightingLIKE, ORDER BY … DESC, LIMIT: the newest rows only.
Chapter 3 · faces and clubsJOIN across a chain of foreign keys; LEFT JOIN keeps rows with no match (people without a club), an inner JOIN silently drops them.
Chapter 4 · shopping listWHERE filters rows, GROUP BY forms groups, HAVING filters groups.
Chapter 5 · broken alibiSub-queries with NOT IN / NOT EXISTS: a query whose condition is the result of another query.
Chapter 6 · follow the cardIndexes. The plan panel counts the rows the engine had to read: a full scan reads every row, an index jumps to the matching ones. CREATE INDEX makes the same query read about 70 rows instead of 7 700.
Plan panelThe query plan: full scan or index search, and the work done. It is a simulation of how a real database engine decides.
“Did you mean…?” errorsThe engine checks every name against the schema, so a typo in a table or column is reported with a suggestion.
Case board and accusationData answers questions only when you combine several independent facts. The culprit is the only person who satisfies all four filters at once; each filter alone leaves several suspects.
