Program the CPU

Each level hands the toy computer from Chapter 7 some numbers and a target output. You write the assembly; the machine runs it one register transfer at a time, so you can watch fetch, decode, execute do your bidding.

How to play. Pick a level, edit the program, then Step or Run to watch it, and press Check all tests to score it. You earn up to three stars per level: solved, small (few instructions) and fast (few fetch–decode–execute cycles). The memory is tiny, there is no immediate-operand instruction (constants live in .data cells) and the accumulator R starts at 0. This is a simulation of the course's teaching machine, not a real x86 or ARM CPU.

What am I looking at?
  • Memory grid. One box per numbered cell. Your instructions and your data sit in the same memory: this is the stored-program idea. The cell under the amber outline is where PC points; blue shows a read, green a write.
  • PC (program counter). The address of the next instruction. A normal step adds 1; JUMP and a taken conditional jump overwrite it, which is how loops and if-else exist.
  • MAR and MDR. The memory address register holds which cell is being accessed, the memory data register holds what was read or is about to be written. Every memory access passes through this pair.
  • IR and the decoder. The fetched word is copied into IR; the decoder splits it into a 4-bit opcode and an address field. Words in .data are only numbers: if the PC ever reaches one, the machine tries to run it as code.
  • R, the ALU and the flags. ADD and SUBTRACT work on R and a memory cell. COMPARE sets GT, EQ or LT, and the conditional jumps read those flags: that is all an if or while is, at this level.
  • Cycle vs tick. A cycle is one whole instruction (fetch, decode, execute). A tick is one register transfer inside it. The fast star counts cycles; size counts instruction cells, and a JUMPGE/JUMPLE pseudo-instruction costs two.
  • Size versus speed. A loop saves instructions but spends cycles on bookkeeping (counter, compare, jump). Straight-line code is longer but quicker. Real compilers and CPUs face the same trade-off.
  • Input and output. IN takes the next number from the input queue; OUT prints a cell. In this game, if the program asks for input when the queue is empty the run simply ends, so a short loop can replace HALT.
