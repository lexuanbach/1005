Von Neumann Machine

The toy computer of Chapter 7 as a small workbench: write assembly in a real editor, pick from more than 60 examples, and watch fetch, decode, execute move values from register to register. Then change the machine itself: its memory, its instruction set, how slow its memory is.

How to use it. Press Examples to load a program with a story, tests and challenges, or write your own in the editor (mistakes are marked as you type). Micro-step shows one arrow at a time; Play runs on with a breakpoint stop (click the gutter or press F9); Run to end skips the animation. Use the tabs below the diagram for the memory, the assembled Listing, the Trace, the cycle Stats, your own Tests and the Reference. Settings changes the machine. Save, Download and Share keep your programs. This is a simulation of the course's teaching machine, not a real x86 or ARM CPU.

What am I looking at?
  • The diagram. Blocks are the machine's parts; every arrow is one register transfer. A value travels along it (it keeps the colour of the block it left; the receiving block lights up) and the registers update when it lands. Numbers enter from the input queue and leave through the output device. The speed slider sets the pace; Instant skips the animation.
  • PC (program counter). The address of the next instruction. A normal step adds 1; JUMP and a taken conditional jump overwrite it, which is how loops and if-else exist.
  • MAR and MDR. The memory address register holds which cell is being accessed, the memory data register holds what was read or is about to be written. Every memory access passes through this pair.
  • IR and the decoder. The fetched word is copied into IR; the decoder splits it into an opcode and an address field. Words in .data are only numbers: if the PC ever reaches one, the machine tries to run it as code.
  • R, the ALU and the flags. ADD and SUBTRACT work on R and a memory cell. COMPARE sets GT, EQ or LT, and the conditional jumps read those flags: that is all an if or while is, at this level.
  • Memory. One row per numbered cell, in the memory block's colour. Instructions and data sit in the same memory: the stored-program idea. Small tags show what the machine touches: PC the next instruction, MAR the cell the address register holds, read the cell just copied into MDR, write the cell just overwritten.
  • Extended instruction set. In Settings you can switch on 12 supplementary instructions: immediate values (LOADI), pointers (LOADP, STOREP), MUL, DIV, MOD. They are not on slide 34; they show why real CPUs grew more instructions. Words become one bit wider.
  • Memory latency and the bottleneck. Raise the latency and every instruction fetch, data read and data write costs more cycles while register transfers stay at 1. The Stats tab shows which share of the cycles is spent waiting for memory: the Von Neumann bottleneck of slide 35.
  • Wrap-around cells. Real hardware has fixed-width cells: with 8 bits, 127 + 1 becomes −128. Switch it on in Settings and watch a counter overflow.
  • Input and output. IN takes the next number from the input queue (type numbers separated by spaces); OUT prints a cell into the output log. If the queue is empty the machine waits for you.
