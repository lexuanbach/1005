Inside IntegersSupplementary

S3 showed how doubles bend reality; integers are exact — until they run out of room. This topic shows how int really lives in memory: two's complement, the one representation that lets the same adder circuit handle positive and negative numbers alike. You will see why −1 is all ones, why the range is lopsided, and what actually happens the moment 127 + 1 wraps around to −128.

01 · The idea

One negative place value fixes everything

S4.1Bits are just place values

An unsigned 8-bit number is ordinary binary: each bit is worth 128 · 64 · 32 · 16 · 8 · 4 · 2 · 1, giving 0 … 255. But that has no room for negatives — and computers need them.

Two's complement changes exactly one thing: the top bit's weight becomes negative. In 8 bits it counts as −128 instead of +128:

reading −5 in 8 bits
bit weights:   −128  64  32  16   8   4   2   1
−5 = 11111011:    1   1   1   1   1   0   1   1

value = −128 + 64 + 32 + 16 + 8 + 2 + 1 = −5
  • Top bit 0 → the number is ≥ 0, and reads like plain binary.
  • Top bit 1 → the number is negative. That is why it is called the sign bit — but it also carries value (−2⁷), it is not just a flag.
  • −1 is all ones: −128 + 127 = −1. Every width: 0xFF, 0xFFFF, 0xFFFFFFFF.

S4.2Negating a number: invert every bit, add 1

−x = ~x + 1 (negating 5)
 5  =  00000101
invert 11111010
 + 1   11111011  =  −5   ✓

Try it in the Lab below — the negate button shows all three rows for any number, including the one weird case the rule cannot handle.

S4.3Why this representation won: the adder doesn't care

The magic of two's complement is that the ordinary binary adder gives the right answer for signed numbers too — no special circuit for negatives:

2 + (−5), computed by a plain adder
  00000010      (  2 )
+ 11111011      ( −5 )
──────────
  11111101      ( −3 )   ✓  same wires, correct signed result

The CPU adds, subtracts, and compares signed and unsigned numbers with the same hardware — only your program's type decides how the bit pattern is read. The Lab shows both readings of every pattern side by side.

02 · When the room runs out

Overflow: 127 + 1 = −128

S4.4The wrap-around, bit by bit

the largest 8-bit value, plus one
  01111111      ( 127, the maximum )
+ 00000001
──────────
  10000000      ( −128 — the carry marched into the sign bit! )

Nothing “breaks” electrically — the carry simply ripples into the negative-weight bit and the value teleports from the top of the range to the bottom. The ranges, and one crucial C++ rule:

TypeBitsSigned range
char8−128 … 127
short16−32,768 … 32,767
int32−2,147,483,648 … 2,147,483,647
long long64about ±9.2 × 10¹⁸
C++ rule Overflowing an unsigned type is well defined — it wraps modulo 2ⁿ. Overflowing a signed type is undefined behaviour: the compiler is allowed to assume it never happens, and optimized programs can do truly strange things when it does. If your sums can reach billions, use long long.
Notice the asymmetry There is a −128 but no +128 (zero uses up one of the “positive” patterns). That is why negating the minimum value is the one case invert-and-add-one cannot handle — press negate on −128 in the Lab and watch it give −128 straight back.

And one familiar face: char is just an 8-bit integer. That is why Chapter 3's 'a' + 1 == 'b' works — 'A' is 65. Encode it in the Lab and read its bits.

S4.5Overflow in the wild

Overflow is not a classroom curiosity — it ships in real products. A one-line C++ example that looks completely innocent:

seconds_per_century.cpp — spot the bug
int secondsPerCentury = 100 * 365 * 24 * 60 * 60;
// 3,153,600,000 — but INT_MAX is 2,147,483,647.
// The multiplication overflows BEFORE the assignment:
// every factor is an int, so the arithmetic is int arithmetic.
// Fix: make one factor wider —  100LL * 365 * 24 * 60 * 60
  • YouTube, 2014: the view counter was a 32-bit int — then PSY's Gangnam Style passed 2,147,483,647 views and YouTube had to move the counter to 64 bits.
  • Ariane 5, 1996: a velocity value was converted into a 16-bit integer that could not hold it; the overflow cascaded and the rocket was destroyed 37 seconds after launch — roughly $370 million.
  • Boeing 787: a generator-control counter overflowed after 248 days of continuous power, prompting an airworthiness directive to reboot the aircraft before then.
Honest note about the exercise boxes The chapter pages' C++ playground interprets numbers with wide precision, so it does not reproduce real 32-bit wrapping — that is exactly what the Lab below is for: set 32-bit, encode 2147483647, press +1, and watch the real thing happen.
03 · Mini app

Two's Complement Lab — integers to bits and back

Type an integer and press Encode — or click any bit to flip it. The readout shows the same bits read as signed and as unsigned, the hex, and the full place-value sum. Use +1 / −1 to walk right off the edge of the range, and negate to watch invert-and-add-one happen row by row. Switch widths to see the same story at 8, 16, and 32 bits.

Things to try Encode 127 at 8 bits and press +1. Encode 255 and compare the signed and unsigned readings of the same bits. Press negate twice on 5 — and then once on −128. Flip the sign bit of 0 and read the place-value sum. Switch to 32-bit, encode 2147483647, and press +1 — that is exactly the bug that has crashed real systems.
