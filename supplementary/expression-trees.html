From Expression to Computation TreeSupplementary

Why is 8 + 5 * 7 % 2 * 4 equal to 12 and not something else? Because the compiler never reads an expression left to right the way you do — it builds a computation tree from the precedence rules, then evaluates that tree from the bottom up. Once you can see the tree, precedence stops being a table to memorize and becomes a picture.

01 · The idea

Precedence is really a tree shape

S2.1Operators become nodes, operands become leaves

Take a + b * c. Precedence says * binds tighter than + — so b * c forms a unit, and + combines a with that unit. Drawn as a tree:

  • Operands (numbers, variables) are the leaves at the bottom.
  • Operators are the internal nodes; each combines the results of its two subtrees.
  • Higher precedence → deeper in the tree → evaluated earlier. The root is the last operation performed, and its value is the value of the whole expression.
  • Associativity breaks ties between equal-precedence neighbours: left-to-right operators like - build a tree leaning left, so 100 - 20 - 5 means (100 - 20) - 5.

S2.2Why the rules exist: one expression, two possible trees

Forget precedence for a moment. The text 8 + 5 * 7 alone is ambiguous — it can be parsed into two different trees with two different answers:

A grammar that permits two parse trees for the same text is called ambiguous — and a compiler must never flip a coin. Precedence and associativity are exactly the tie-breaking rules that make the expression grammar unambiguous: precedence picks between different operators (the second tree wins here), associativity picks between equal ones (100 − 20 − 5 leans left). Once the rules are applied, every expression has exactly one tree.

Ambiguity beyond expressions The most famous grammar ambiguity is not about operators at all: in if (a) if (b) x = 1; else x = 2; — which if owns the else? C++ resolves this dangling else by rule, too: the else attaches to the nearest unmatched if. When in doubt, braces are your parentheses.

S2.3Parentheses reshape the tree — nothing more

( ) never appears in the tree and costs nothing at run time. Writing a * (b + c) simply forces + to sit deeper than * — the opposite of the default shape. That is the whole job of parentheses: they overrule precedence by rearranging which node is inside which, and then they vanish.

S2.4How the compiler evaluates the tree

The compiler walks the tree bottom-up: to produce the value of a node, first produce the values of its children (a post-order walk), then apply the node's operator. For a + b * c it therefore emits machine code for the deep * first and the root + last:

a + b * c — the tree, flattened into instructions (simplified)
mov  eax, [b]     ; load the leaf b
imul eax, [c]     ; eax = b * c   — the deeper node runs FIRST
add  eax, [a]     ; eax = a + b*c — the root runs LAST

This is also exactly why C++ can apply integer division node by node: in 9 / 2 * 3, the node 9 / 2 produces the int 4 before the * node ever sees it — giving 12, not 13.5.

Constant folding When a whole subtree contains only constants — like every example on this page — a real compiler evaluates it at compile time and just emits the answer. Your 8 + 5 * 7 % 2 * 4 ships as the single constant 12.

S2.5Short-circuit is a tree walk that stops early

For && and || (Chapter 3), the walk evaluates the left subtree first — and if that already decides the answer, the entire right subtree is never visited. In the Tree Lab below, load the short-circuit example and watch the right half of the tree grey out.

02 · Mini app

Tree Lab — type an expression, watch it compute

Type any numeric C++ expression (arithmetic, comparisons, &&, ||, !, parentheses) and press Build the tree. The fully parenthesized reading shows exactly how precedence grouped it. Then press Step: each click evaluates one operator node — deepest first, root last — turning its result green on the tree.

Things to try Compare 15 / 2 * 2 with 15.0 / 2 * 2 — one decimal point changes a whole node's type. Add parentheses to 8 + 5 * 7 % 2 * 4 until it evaluates to 84. Then load the short-circuit example and count how many operators are never evaluated. Try 5 / 0 and 1 / 0 == 1 || 1 — which one survives, and why?
