The Call StackSupplementary

One picture explains half of Chapter 6: every function call pushes a frame onto a stack, every return pops it. Locals live and die with their frame — that is why auto resets. static and globals live outside the stack — that is why they remember. References are arrows into another frame. And recursion is just many frames of the same function, each with its own variables.

01 · The idea

Frames: where variables actually live

S7.1Call = push, return = pop

When main calls findMax(a, b), the machine pushes a stack frame for findMax: a fresh workspace holding its parameters (copies, for pass-by-value — Chapter 6's central rule) and its local variables, plus a note of where in main to resume. When findMax returns, its frame is popped — the workspace, and every local in it, is gone. The value travels back; the variables do not.

S7.2Why auto resets and static remembers

Chapter 6's Examples 6.4.1 and 6.4.2 stop being mysterious the moment you see where each variable lives. An auto local lives in the frame: new call, new frame, new variable, initialized again — 0, 0, 0. A static local lives outside the stack, in the same region as globals: it is created once, survives every pop, and greets the next call with its old value — 0, 1, 2. Scope and lifetime are different questions: the static's scope is still just its function; only its lifetime is the whole program.

S7.3References are arrows between frames

A pass-by-value parameter is a copy inside the callee's frame — squaring it disturbs nobody. A reference parameter (int &cRef) is an arrow pointing back into the caller's frame: assignments travel along the arrow and land in the caller's variable while its frame sits suspended below. Watch the third preset — while squareByReference is on top of the stack, main's z changes underneath it.

S7.4Recursion — and the stack's limit

fact(4) calls fact(3) before it can finish — so both frames are alive at once, each with its own n. The stack grows four frames deep, then unwinds pop by pop as the returns multiply back up. And because the stack is finite memory, recursion without a base case pushes frames until it runs out: the crash every programmer eventually meets, called a stack overflow.
