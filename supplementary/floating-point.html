Inside Floating PointSupplementary

Chapter 2 told you floating point numbers are “always approximate” and to avoid ==. This topic shows you exactly why — down to the last of the 55 decimal digits your computer really stores for 0.1 — and walks the famous mystery step by step: why 0.1 + 0.2 == 0.3 is false. The IEEE 754 Lab below lets you turn any number into its bits and flip them back.

01 · The format

How a real number becomes bits

S3.1Sign, exponent, mantissa — scientific notation in binary

IEEE 754 stores every number the way scientists write big numbers — as ± 1.fraction × 2exponent — just in base 2:

  • Sign (1 bit): 0 = positive, 1 = negative.
  • Exponent: stored with a bias added so that negative exponents need no sign of their own — a float stores E = e + 127, a double stores E = e + 1023.
  • Mantissa (the fraction): the digits after “1.” — the leading 1 of every normal number is implicit, so it is never stored. One whole bit of precision, free.
float (32-bit)double (64-bit)
sign · exponent · mantissa1 · 8 · 231 · 11 · 52
exponent bias1271023
reliable decimal digits~7~15–16
largest value≈ 3.4 × 10³⁸≈ 1.8 × 10³⁰⁸

Special bit patterns cover the edge cases: all-zero exponent and mantissa is zero; all-ones exponent is ±infinity (mantissa 0) or NaN (mantissa ≠ 0). Overflowing a float — try 3.4e39 in the Lab — lands you on infinity.

S3.2Why 0.1 cannot be stored exactly

Convert 0.1 to binary by repeated doubling — the integer part of each doubling is the next binary digit:

Step× 2Binary digit
0.10.20
0.20.40
0.40.80
0.81.61
0.61.21
0.20.40 — we are back at 0.2: it repeats forever

So 0.1 in binary is 0.0001100110011001100…₂ — an infinite repeating fraction, like 1/3 = 0.333… in decimal. A double has only 52 mantissa bits, so the tail must be rounded off. The value that actually lands in memory is the nearest representable double:

what “double x = 0.1;” really stores
0.1000000000000000055511151231257827021181583404541015625

A decimal fraction is exact in binary only when its denominator is a power of two: 0.5, 0.25, 0.75, 2.75 store perfectly; 0.1, 0.2, 0.3 never can.

02 · The mystery, solved step by step

Why 0.1 + 0.2 ≠ 0.3

S3.3Three roundings, one surprise

Every number below is exact — verified bit-for-bit (check them yourself in the Lab):

StepExact value involved
1. 0.1 is stored as 0.1000000000000000055511151231257827021181583404541015625
2. 0.2 is stored as 0.200000000000000011102230246251565404236316680908203125
3. the CPU adds them exactly 0.3000000000000000166533453693773481063544750213623046875
4. …but that sum is not representable either, so it is rounded to the nearest double 0.3000000000000000444089209850062616169452667236328125
5. meanwhile 0.3 is stored as 0.299999999999999988897769753748434595763683319091796875

Step 4 rounded up; step 5 rounded down. The two results are different doubles — they differ in their very last bit — so 0.1 + 0.2 == 0.3 is false, and cout << 0.1 + 0.2 with enough precision prints 0.30000000000000004.

see_it_yourself.cpp
#include <iostream>
#include <iomanip>
using namespace std;

int main() {
    cout << setprecision(17);
    cout << 0.1 + 0.2 << endl;             // 0.30000000000000004
    cout << (0.1 + 0.2 == 0.3) << endl;    // 0  (false!)
}

S3.4So what should you do?

  • Never compare doubles with ==. Compare against a tolerance instead:
epsilon_compare.cpp
#include <cmath>

bool nearlyEqual(double a, double b) {
    return fabs(a - b) < 1e-9;   // close enough counts as equal
}
  • Money: count in integer cents / nghìn đồng, not in fractional currency — integers are exact.
  • Know your budget: a float carries ~7 reliable decimal digits, a double ~15–16. Accumulated arithmetic eats into that budget — which is why scientific computation defaults to double.
03 · Mini app

IEEE 754 Lab — numbers to bits and back

Type a number and press Encode to see its sign, exponent, and mantissa bits — plus the exact value those bits represent, every digit. Then go the other way: click any bit to flip it and watch the decimal value change. Switch between double (64-bit) and float (32-bit) to see precision shrink before your eyes.

Things to try Encode 0.1, then press the 0.1 + 0.2 and 0.3 presets and compare their last mantissa bits — that single-bit difference is the whole famous bug. Flip the sign bit. Flip the last mantissa bit of 1 and read how tiny the change is. Switch 0.1 to 32-bit float and watch the error grow. Encode 3.4e39 as a float — welcome to infinity.
