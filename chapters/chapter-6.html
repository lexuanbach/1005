Programs made of named pieces

6.1Definitions, calls, and the two kinds of parameter

In C++ all subprograms are functions. A function definition has four parts: the return data type, the name, any parameters within ( ), and the body in { }:

Did you know? The function is older than every programming language you have heard of. Maurice Wilkes, David Wheeler and Stanley Gill — authors of the 1951 book Preparation of Programs for an Electronic Digital Computer — are generally credited with inventing what they called the “closed sub-routine” — although Alan Turing had already described subroutines, down to a stack of return addresses, in a 1945 design paper. Source: Wikipedia — Function (history).
example_6_1_1.cpp
void FindMax(int x, int y) {        // x, y: FORMAL parameters
    int maxnum;
    maxnum = (x >= y) ? x : y;
    cout << "The maximum of the 2 numbers is " << maxnum << endl;
}

// in main():
int firstNum = 5, secNum = 8;
FindMax(firstNum, secNum);            // firstNum, secNum: ACTUAL parameters

The names in the function header are formal parameters; the values or variables placed in the call are actual parameters.

Functions break large computing tasks into smaller ones, and enable people to build on what others have done instead of starting over from scratch.

Brian W. Kernighan & Dennis M. Ritchie, The C Programming Language, opening line of Chapter 4, “Functions and Program Structure” — written about C, but it is the whole reason this chapter exists. Portraits: Brian Kernighan — Jw12321, 2025 · CC0 (public domain dedication); Dennis Ritchie — Denise Panyik-Dale, 2011 · CC BY 2.0 (cropped)
A function can call itself Nothing in the rule above says the function being called has to be a different one — a function is allowed to call itself, which gives you a second way to repeat something besides the loops of Chapter 4. 6.2Prototypes — promise now, define later

A function prototype declares to the compiler that you intend to use a function later: int maximum(int, int, int); (parameter names optional). Calling a function before either its prototype or its definition is a compile-time error. Example 7.3.2 puts the prototype above main, the call inside it, and the definition below — the standard layout you will use in Exercise 2.

Did you know? Here the child taught the parent. Classic “K&R” C had no prototypes, so the arguments of a call were not type-checked. When C was standardized in 1989, the committee added function prototypes borrowed from C++ — one of the few features that flowed from the younger language back into the older one. Source: Wikipedia — C (ANSI C and ISO C).

If I have seen further it is by standing on ye sholders of Giants.

Isaac Newton, letter to Robert Hooke (February 1676), in his own spelling — a prototype is how a programmer climbs up. One line such as double sqrt(double); is all you need to know to call a function somebody else wrote, tested and perfected; how it works inside can stay their business. 6.3Pass by value — the function gets a copy

When a variable is an actual parameter, the called function receives a copy of its value. Changes to the copy never affect the caller's variable. To hand a result back, use return expression; (or the bare return; in a void function) — and the value's type must match the function's declared return type.

6.4Scope: global vs local

Scope is where a declared name may be used. Declared outside every function → global scope, accessible throughout the program. Declared inside a function → local scope, that function only. Example 6.3.1 is the classic trace: a global x changed inside valfun() stays changed for main (x = 40), while each function's local y is its own — main's y is still 20.

Read next learncpp.com — Why (non-const) global variables are evil takes Example 6.3.1 further: a global that any function can quietly change is exactly the kind of shared state behind 6.5's true story below.

6.5Storage classes — how long a variable lives

A variable's lifetime is its storage duration (storage class): auto, static, extern, and register. Locals may be auto (the default), static, or register.

auto_vs_static.cpp — one word changes everything
void testauto()   { int num = 0;        cout << num; num++; }
// three calls print: 0 0 0   — created and destroyed every call

void teststatic() { static int num = 0; cout << num; num++; }
// three calls print: 0 1 2   — created ONCE, remembered for the
//                              life of the program
Did you know? Two of these four keywords have since changed their lives. Since C++11, auto no longer names a storage class — it now asks the compiler to work out a variable's type, as in auto x = 3.5;. And register stopped being a storage class specifier in C++17: the word is still reserved, but it no longer does anything. Source: cppreference — Storage class specifiers.
  • A static local's initialization happens only once; with no explicit initializer, statics are set to zero. Example 6.4.4's static int sum = 100; accumulates: 101, 103, 106, 110…
  • register asks for storage in the CPU's internal registers; same duration as auto.
  • extern names a global that is defined in another file, so several files can share it.
True story · the Knight Capital trading glitch, 2012 Leftover state that outlives the function that used it is not just a classroom worry. Preparing new order-routing code for the NYSE, engineers at Knight Capital repurposed a flag that used to switch on a retired feature called “Power Peg”. Rather than deleting Power Peg's old code, they planned for the flag to simply never reach it again.
SMARS order router (reconstructed from the SEC order, ¶¶13–16)
// years earlier: Power Peg's own share-counting check had been moved
// EARLIER in the sequence, and never retested after the move
if (repurposedFlag == "yes") {
    runNewRLPCode(order);        // the 7 correctly-updated servers ran this
}
// this branch was meant to be deleted, but the deployment never removed it:
else {
    runPowerPegCode(order);       // dead code — unused, but still callable
}

One of eight production servers never received the new code. On that single server the same repurposed flag activated the dormant Power Peg branch instead — code whose own running-total logic had quietly stopped working years earlier. For 45 minutes it fired uncontrolled buy and sell orders into the market: 4 million executions across 154 stocks, 397 million shares, a $460 million loss. Read the SEC's order against Knight Capital for the full account. In this course: code that is merely unreachable today is still callable — deleting it is safer than trusting a flag to keep it switched off forever.

6.6Pass by reference — the & that changes the caller

Follow the parameter's type with an ampersand and the callee can access — and modify — the caller's data directly:

example_6_5_1.cpp
int squareByValue(int a) {
    return a *= a;      // squares a COPY — caller's x unchanged
}

void squareByReference(int &cRef) {
    cRef *= cRef;       // squares the caller's own variable
}

// x = 2 → still 2 after squareByValue(x)  (which returned 4)
// z = 4 → becomes 16 after squareByReference(z)

Choose by-value when the function only needs to read; choose by-reference when its job is to change its arguments — like swap, or a function that must hand back more than one result.

Data abstractions provide the same benefits as procedures, but for data.

Barbara Liskov, keynote “Data Abstraction and Hierarchy”, OOPSLA (1987) — a function already abstracts over how; a reference parameter is how that abstraction reaches back out and touches the caller's own data. Portrait: Kenneth C. Zirkel, 2010 · CC BY-SA 3.0 (cropped)

6.7Passing arrays to functions

Pass an array by its name, without brackets: modifyArray(hourlyTemperature, size). The receiving parameter is declared as int b[] — the size is not required between the brackets, which is exactly why the element count travels as its own parameter.

example_6_6_1.cpp — linear search
int linearSearch(int array[], int key, int sizeofArray) {
    for (int n = 0; n < sizeofArray; n++)
        if (array[n] == key)
            return n;       // found: its position
    return -1;              // a sentinel: no valid index is −1
}
Arrays break the copy rule Unlike single values, an array is not copied into the function — the callee works on the caller's elements, so modifications are visible after the call. Arrays are effectively passed by reference.
Did you know? Even a search routine can hide a bug for decades. The faster cousin of this function, binary search, was first published in 1946, yet according to Jon Bentley the first version correct for all sizes appeared only in 1962. In 2006 Joshua Bloch found that the one he had written for Java's standard library had been wrong for nine years: (low + high) / 2 overflows int once an array holds about a billion elements. Source: Joshua Bloch, Google Research blog (2006).

What I cannot create, I do not understand.

Richard Feynman, written on his Caltech blackboard, still there when he died in February 1988 — the standard library already ships a linear search, std::find. You write linearSearch by hand first for Feynman's reason: once you have built it yourself, no search function is a black box again. 04 · Team activity

Group discussion: the great refactor

Teams of 3–4 · one class period to prepare · a 5-minute before/after presentation. Counts toward the class-activities 10%.

Every piece of knowledge must have a single, unambiguous, authoritative representation within a system.

Andy Hunt & Dave Thomas, The Pragmatic Programmer (the DRY principle) — a duplicated loop, copy-pasted three times across your Chapter 4/5 program, is exactly the knowledge this refactor is meant to give a single home: one function. Portraits: Andy Hunt — Kittie Rue · CC BY-SA 3.0 (cropped); Dave Thomas — James Davidson, 2006 · CC BY 2.0 (cropped)

The task

Take one long, working, function-free program — your team's Chapter 4 survey machine or Chapter 5 gradebook is perfect — and refactor it into functions. The deliverable is an API design the team can defend: a list of function prototypes where every parameter is deliberately by-value, by-reference, or an array — with one sentence of justification each.

Constraints that force Chapter 6 thinking

  • main() shrinks to a readable sequence of calls — no loose loops left in it.
  • At least one function returns a value, one uses a reference out-parameter, and one takes an array plus its size.
  • No global variables — everything travels through parameters. (If the team keeps one, they must defend it against the scope section of this chapter.)
